# Django ORM (Object-Relational Mapping) – Complete Notes

## 1. What Is ORM?

ORM stands for **Object-Relational Mapping**.

Django ORM allows us to interact with a database using Python code instead of writing SQL queries manually.

For example, we can retrieve all employees using:

```python
Employee.objects.all()
```

Instead of writing SQL:

```sql
SELECT * FROM employee;
```

Django converts ORM operations into appropriate database queries.

### How Django ORM works

```text
Python Code
    |
    v
Django ORM
    |
    v
SQL Query
    |
    v
Database
    |
    v
QuerySet / Model Objects
```

### Advantages of Django ORM

- Reduces the need to write SQL manually.
- Makes database operations easier using Python.
- Supports databases such as SQLite, PostgreSQL and MySQL.
- Provides filtering, sorting, aggregation and relationship handling.
- Helps protect against SQL injection when used correctly.

## 2. Understanding `Model.objects`

Consider the following model:

**`models.py`**

```python
from django.db import models

class Employee(models.Model):
    name = models.CharField(max_length=100)
    address = models.CharField(max_length=200)
    salary = models.IntegerField()

    def __str__(self):
        return self.name
```

Here:

- `Employee` is the model class.
- `objects` is the default model manager.
- `all()`, `filter()`, `get()` and other methods are used to retrieve or manipulate data.

Most retrieval methods return a **QuerySet**, which represents a collection of database results. A QuerySet is generally evaluated lazily, when its results are needed.

## 3. Retrieve All Records — `all()`

The `all()` method retrieves all records for a model.

```python
employees = Employee.objects.all()
```

Equivalent SQL:

```sql
SELECT * FROM employee;
```

Example:

```python
for employee in Employee.objects.all():
    print(employee.name, employee.salary)
```

**Use case:** Displaying all employees on a webpage.

## 4. Retrieve a Single Record — `get()`

The `get()` method retrieves exactly one matching record.

```python
employee = Employee.objects.get(id=1)
```

You can also use the primary-key shortcut:

```python
employee = Employee.objects.get(pk=1)
```

`pk` refers to the model's primary key, which is often the automatically generated `id` field.

### Important behavior

`get()` raises an exception if:

- No matching record exists: `Employee.DoesNotExist`
- More than one matching record exists: `Employee.MultipleObjectsReturned`

Example:

```python
try:
    employee = Employee.objects.get(pk=1)
    print(employee.name)

except Employee.DoesNotExist:
    print("Employee not found")
```

Use `get()` when you expect exactly one record.

### 4.1 Exact matching — `exact`

```python
Employee.objects.get(id__exact=14)
```

This finds the employee whose ID is exactly `14`.

The following is usually equivalent:

```python
Employee.objects.get(id=14)
```

### 4.2 Case-insensitive exact matching — `iexact`

```python
Employee.objects.filter(name__iexact="shiv")
```

This matches the name without distinguishing letter case, subject to the database's comparison behavior.

For example, it may match `"Shiv"`, `"SHIV"` and `"shiv"`.

Use `filter()` when multiple records could match.

### 4.3 Containment matching — `contains`

```python
Employee.objects.filter(name__contains="shiv")
```

This finds names containing `"shiv"`. It is case-sensitive according to the database's behavior.

For a case-insensitive containment search, use:

```python
Employee.objects.filter(name__icontains="shiv")
```

**Remember:** `get()` is for exactly one result. Use `filter()` for zero, one or many results.

## 5. Filter Records — `filter()`

The `filter()` method retrieves records that match specified conditions.

```python
Employee.objects.filter(name="Shiv")
```

You can filter using different model fields:

```python
Employee.objects.filter(salary=100000)

Employee.objects.filter(address="Pune")

Employee.objects.filter(salary__gt=50000)
```

Unlike `get()`, `filter()` returns a QuerySet even when no records match.

### Multiple conditions in one filter

```python
Employee.objects.filter(name="Shiv", salary=100000)
```

This applies both conditions using **AND** logic.

Equivalent SQL concept:

```sql
SELECT * FROM employee
WHERE name = 'Shiv' AND salary = 100000;
```

## 6. Query Lookups

Django provides lookup expressions such as `exact`, `contains`, `gt`, `gte`, `lt`, `lte`, `in` and `range`.

These lookups are appended to a field name using double underscores (`__`).

### 6.1 Comparison lookup table

| Lookup | Meaning | Example |
|---|---|---|
| `exact` | Exact match | `filter(salary__exact=50000)` |
| `iexact` | Case-insensitive exact match | `filter(name__iexact="shiv")` |
| `contains` | Contains text | `filter(name__contains="aj")` |
| `icontains` | Case-insensitive containment | `filter(name__icontains="aj")` |
| `startswith` | Starts with text | `filter(name__startswith="S")` |
| `istartswith` | Case-insensitive start | `filter(name__istartswith="s")` |
| `endswith` | Ends with text | `filter(name__endswith="v")` |
| `gt` | Greater than | `filter(salary__gt=50000)` |
| `gte` | Greater than or equal to | `filter(salary__gte=50000)` |
| `lt` | Less than | `filter(salary__lt=50000)` |
| `lte` | Less than or equal to | `filter(salary__lte=50000)` |
| `in` | Matches any supplied value | `filter(id__in=[1, 2, 3])` |
| `range` | Between two boundary values | `filter(salary__range=(30000, 80000))` |

**Common mistake:** The correct lookup is `startswith`, not `startwith`.

## 7. Filter Using OR, AND and NOT — `Q` Objects

Django provides `Q` objects to build complex query conditions.

Import `Q` as follows:

```python
from django.db.models import Q
```

### 7.1 OR condition (`|`)

Retrieve employees whose names start with `"S"` **or** whose salary is `100000`.

```python
employees = Employee.objects.filter(
    Q(name__startswith="S") | Q(salary=100000)
)
```

A record is returned if either condition matches.

### 7.2 AND condition (`&`)

Retrieve employees whose names start with `"S"` **and** whose salary is at least `50000`.

```python
employees = Employee.objects.filter(
    Q(name__startswith="S") & Q(salary__gte=50000)
)
```

Both conditions must be true.

You can also write this more simply without `Q`:

```python
employees = Employee.objects.filter(
    name__startswith="S",
    salary__gte=50000
)
```

**Note:** A condition requiring a name to start with both `"S"` and `"M"` cannot normally match a nonempty name. Use different fields or alternative conditions if that is what you intend.

### 7.3 NOT condition (`~`)

Retrieve employees whose names do not start with `"A"`.

```python
employees = Employee.objects.filter(
    ~Q(name__startswith="A")
)
```

### 7.4 Combining multiple conditions

```python
employees = Employee.objects.filter(
    (Q(name__startswith="S") | Q(name__startswith="M"))
    & Q(salary__gte=50000)
)
```

This retrieves employees whose names start with `"S"` or `"M"` and whose salaries are at least `50000`.

## 8. Retrieve Records From a List — `in`

The `in` lookup retrieves records whose field value matches any value in a supplied iterable.

```python
employees = Employee.objects.filter(id__in=[1, 2, 3])
```

This retrieves employees with IDs `1`, `2` or `3`.

You can also use names:

```python
employees = Employee.objects.filter(
    name__in=["Shiv", "Akash", "Amit"]
)
```

If you use a string directly:

```python
Employee.objects.filter(name__in="aka")
```

Django treats the string as an iterable of characters, so it effectively searches for names matching individual characters such as `"a"`, `"k"` or `"a"` rather than the complete name `"aka"`.

**Best practice:** Use a list, tuple or another appropriate iterable for `__in`.

## 9. Retrieve Records Within a Range — `range`

The `range` lookup retrieves records whose field values fall between two boundaries, inclusive.

### Example: Salary range

```python
employees = Employee.objects.filter(
    salary__range=(30000, 80000)
)
```

This matches salaries from `30000` through `80000`, including both boundaries.

### Example: Date range

```python
import datetime

start_date = datetime.date(2025, 1, 1)
end_date = datetime.date(2026, 3, 31)

entries = Entry.objects.filter(
    addeddate__range=(start_date, end_date)
)
```

This retrieves records with dates between January 1, 2025 and March 31, 2026, inclusive.

For a `DateTimeField`, be careful when using date boundaries: a date used as the upper bound may represent midnight at the beginning of that date. For an inclusive whole-day interval, a half-open range using the next day's start is often safer.

## 10. Union of QuerySets — `union()`

The `union()` method combines the results of compatible QuerySets.

Example:

```python
employees_s = Employee.objects.filter(
    name__startswith="S"
)

employees_m = Employee.objects.filter(
    name__startswith="M"
)

employees = employees_s.union(employees_m)
```

This combines employees whose names start with `"S"` and employees whose names start with `"M"`.

### Important rules

- Both QuerySets must select compatible columns and data types.
- By default, duplicate rows are removed.
- Use `union(all=True)` when you need to preserve duplicates.
- After `union()`, only certain operations are supported on the resulting QuerySet.

For ordinary filtering, the `Q` object approach is often simpler:

```python
employees = Employee.objects.filter(
    Q(name__startswith="S") | Q(name__startswith="M")
)
```

## 11. Create a Single Record — `create()`

The `create()` method creates and saves a database record in one operation.

```python
employee = Employee.objects.create(
    name="Shiv",
    address="Kailash",
    salary=100000
)
```

Equivalent SQL concept:

```sql
INSERT INTO employee (name, address, salary)
VALUES ('Shiv', 'Kailash', 100000);
```

The returned `employee` variable contains the newly created model object.

**Important:** Supply valid values for all required fields that do not have defaults. A database save can fail if the field values violate model or database constraints.

## 12. Create Multiple Records — `bulk_create()`

`bulk_create()` creates multiple model instances efficiently, generally using fewer database queries than saving each object individually.

```python
Employee.objects.bulk_create([
    Employee(
        name="Shiv",
        address="Kailash",
        salary=100000
    ),
    Employee(
        name="Akash",
        address="Pune",
        salary=80000
    ),
    Employee(
        name="Amit",
        address="Mumbai",
        salary=70000
    ),
])
```

### Important points

- Pass a list or other iterable of model instances.
- Each item must be an instance of `Employee`.
- `bulk_create()` does not call each object's `save()` method.
- Model `pre_save` and `post_save` signals are not sent for each instance.
- Database behavior for returning generated primary keys varies by backend and Django version.

**Common mistake:** This is invalid syntax:

```python
# Incorrect
Employee.objects.bulk_create(
    Employee(name="Shiv", address="Kailash", salary=100000)
)
```

Pass a collection of model instances instead.

## 13. Delete Records

### 13.1 Delete a single record

```python
employee = Employee.objects.get(pk=1)
employee.delete()
```

This retrieves the employee with primary key `1` and deletes it.

You can handle the case where the employee does not exist:

```python
try:
    employee = Employee.objects.get(pk=1)
    employee.delete()

except Employee.DoesNotExist:
    print("Employee not found")
```

### 13.2 Delete multiple records

```python
Employee.objects.filter(name="Akash").delete()
```

This deletes all employees whose names exactly match `"Akash"`.

### 13.3 Delete all records

```python
Employee.objects.all().delete()
```

**Warning:** This deletes every employee record in the table. Use it carefully, especially in production.

### Important deletion behavior

Django's `delete()` method returns a tuple containing the total number of deleted objects and a breakdown by model. Deletion can also affect related objects according to the relationship's `on_delete` setting.

## 14. Select Particular Columns

Django provides `values()`, `values_list()` and `only()` for selecting or loading particular fields.

### 14.1 `values()`

Returns dictionaries containing the selected field values.

```python
employees = Employee.objects.values("name", "salary")
```

Example result:

```python
[
    {"name": "Shiv", "salary": 100000},
    {"name": "Akash", "salary": 80000},
]
```

This is useful when you need data rather than complete model objects.

### 14.2 `values_list()`

Returns tuples containing the selected field values.

```python
employees = Employee.objects.values_list("name", "salary")
```

Example result:

```python
[
    ("Shiv", 100000),
    ("Akash", 80000),
]
```

For a single field, you can request a flat list:

```python
names = Employee.objects.values_list("name", flat=True)
```

Example result:

```python
["Shiv", "Akash", "Amit"]
```

`flat=True` is allowed only when selecting one field.

### 14.3 `only()`

Returns model instances but defers loading the other fields until they are accessed.

```python
employees = Employee.objects.only("name", "address")
```

The results are still `Employee` objects:

```python
for employee in employees:
    print(employee.name)
```

**Important correction:** `only()` does not mean only the specified columns plus the ID are selected in every sense. Django also needs primary-key information to construct model instances, and deferred fields can trigger additional database queries when accessed.

### Difference between `values()`, `values_list()` and `only()`

| Method | Result type | Main use |
|---|---|---|
| `values()` | Dictionaries | Retrieve selected field values |
| `values_list()` | Tuples, or flat values for one field | Retrieve selected values in a compact format |
| `only()` | Model instances with deferred fields | Load model objects while postponing other fields |

## 15. Sorting Records — `order_by()`

The `order_by()` method sorts a QuerySet by one or more fields.

### 15.1 Ascending order

```python
employees = Employee.objects.all().order_by("id")
```

Records are sorted by ID in ascending order.

Ascending order is the default when you specify a field without a minus sign.

### 15.2 Descending order

```python
employees = Employee.objects.all().order_by("-id")
```

The minus sign (`-`) specifies descending order.

### 15.3 Sort by salary

```python
employees = Employee.objects.order_by("salary")
```

### 15.4 Sort by multiple fields

```python
employees = Employee.objects.order_by("name", "-salary")
```

This sorts by name first and salary in descending order within each name group.

**Note:** If you need a predictable order when multiple records have the same value, add a unique field such as the primary key as a final ordering field.

## 16. Other Useful ORM Methods

| Method | Purpose | Example |
|---|---|---|
| `exclude()` | Exclude matching records | `Employee.objects.exclude(salary=50000)` |
| `first()` | Return the first matching object or `None` | `Employee.objects.order_by("id").first()` |
| `last()` | Return the last matching object or `None` | `Employee.objects.order_by("id").last()` |
| `exists()` | Check whether any matching records exist | `Employee.objects.filter(name="Shiv").exists()` |
| `count()` | Count matching records | `Employee.objects.filter(salary__gt=50000).count()` |
| `distinct()` | Remove duplicate result rows | `Employee.objects.values("name").distinct()` |
| `latest()` | Return the latest object by a date field | `Entry.objects.latest("addeddate")` |
| `earliest()` | Return the earliest object by a date field | `Entry.objects.earliest("addeddate")` |
| `get_or_create()` | Retrieve an object or create it if absent | `Employee.objects.get_or_create(name="Shiv", defaults={"address": "Pune", "salary": 50000})` |
| `update_or_create()` | Update an existing object or create one | `Employee.objects.update_or_create(name="Shiv", defaults={"salary": 80000})` |

For `latest()` and `earliest()`, ensure the chosen date field is appropriate and that the queryset contains a matching record; otherwise, Django may raise an exception.

**Final tip:** Learn ORM methods by using them with a small model, checking the returned Python objects, and comparing the results with the equivalent SQL query. This makes filtering, sorting and CRUD operations much easier to understand.
